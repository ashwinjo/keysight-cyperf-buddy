## Standard Stack

### Backend Email
- **Primary approach:** Python `smtplib` (standard library) + FastAPI `BackgroundTasks`
- **Rationale:** No external service required (Keysight-managed SMTP); single hardcoded credential; simple for Phase 4.1 scope
- **Alternative:** FastAPI-Mail library (wrapper around smtplib with Jinja2 templating). Reasonable but adds dependency for minimal benefit.
- **Why NOT SendGrid/Mailgun:** Adds external service dependency, auth complexity, and cost. Not justified for single hardcoded recipient (ashwin.joshi@keysight.com).

### Frontend Forms
- **Pattern:** React Hook Form + Zod + shadcn/ui components
- **Rationale:** Matches existing shadcn/ui stack; minimal re-renders; type-safe validation
- **Sidebar component:** shadcn/ui Sidebar (drawer pattern) or custom Sheet component for modal-like behavior
- **State management:** React Hook Form (local component state) + optional localStorage for data persistence

### Async Task Handling
- **Choice:** FastAPI `BackgroundTasks` (NOT Celery, NOT APScheduler)
- **Rationale:**
  - Email sends are short-lived (SMTP handshake + send < 5 seconds under normal conditions)
  - No need for distributed workers or multiple processes
  - No external message broker (Redis/RabbitMQ) requirement
  - Same-process execution sufficient for form submissions
  - Scales to thousands of daily submissions without queue management overhead
- **When BackgroundTasks is insufficient:** If retries, failure tracking, or email queuing exceeds Phase 4.1 scope
- **Note:** APScheduler (already in project) is for periodic jobs (Cyperf sync), not request-triggered tasks

### Email Sending
- **Protocol:** SMTP over TLS (port 587 or 465)
- **Credentials:** Environment variables loaded via `pydantic-settings` (matches Cyperf pattern in config.py)
- **Body format:** Plain text (HTML optional, but plain text is safer and sufficient)
- **Template strategy:** f-strings or string .format() — no Jinja2 needed for Phase 4.1

## Architecture Patterns

### Request → Response → Background Email Flow

```
1. User submits contact form (name, company, email, CVE context)
2. Backend validates form (Pydantic model)
3. Backend renders email body (no database write; stateless)
4. Response returns to frontend immediately with success message
5. BackgroundTasks queues email send after response
6. Email sends asynchronously (user doesn't wait)
7. If email fails: logged, not surfaced to user (fire-and-forget acceptable for Phase 4.1)
```

**Why stateless:** No customer database needed yet. Email sent once, archive if needed later.

### Form Submission Endpoint

```python

# Input: ContactFormRequest (first_name, last_name, company, email, cve_id, context_type)
# Output: ContactFormResponse (success: bool, preview_html: str, message: str)
# Side effect: Background email queued via BackgroundTasks
```

**Email preview:** Returned to frontend (user sees exactly what was sent to Ashwin).


## Don't Hand-Roll

### 1. **Email Validation**
- ✓ **DO:** Use `pydantic.EmailStr` or Zod email validation
- ✗ **DON'T:** Regex email validation (too error-prone)

### 2. **Email Sending Retry Logic**
- ✓ **DO:** Log failure; let BackgroundTasks fail silently (acceptable for Phase 4.1)
- ✗ **DON'T:** Build custom retry queue (use BackgroundTasks with basic try-except)
- ✗ **DON'T:** Implement exponential backoff (not needed for single submission)

### 3. **Credential Storage**
- ✓ **DO:** Environment variables via pydantic-settings
- ✗ **DON'T:** Hardcoded strings in source files
- ✗ **DON'T:** Store credentials in database
- ✗ **DON'T:** Pass credentials in logs (redact in error messages)

- ✓ **DO:** Client-side (Zod) + Server-side (Pydantic)

## Email Service Integration

### SMTP Configuration

**Environment variables needed:**
```bash
SMTP_SERVER=mail.keysight.com          # or other internal SMTP relay
SMTP_PORT=587                           # or 465 for implicit TLS
SMTP_USERNAME=cyperf-tracker@keysight.com
SMTP_PASSWORD=<secure-generated>        # rotated, application-specific
SMTP_FROM_EMAIL=cyperf-tracker@keysight.com
SMTP_RECIPIENT_EMAIL=ashwin.joshi@keysight.com
```

**Python implementation (standard library):**
```python
import smtplib
import ssl
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart

def send_email(
    to_email: str,
    subject: str,
    body: str,
    smtp_config: dict
) -> None:
    """Send email via SMTP (fire-and-forget)."""
    context = ssl.create_default_context()  # CRITICAL: validates certs

    with smtplib.SMTP(smtp_config["server"], smtp_config["port"]) as server:
        server.starttls(context=context)
        server.login(smtp_config["username"], smtp_config["password"])

        msg = MIMEText(body, "plain")
        msg["Subject"] = subject
        msg["From"] = smtp_config["from_email"]
        msg["To"] = to_email

        server.sendmail(
            smtp_config["from_email"],
            to_email,
            msg.as_string()
        )
```

**Why NOT alternative services:**
- SendGrid: Requires API key management + API calls (unnecessary complexity)
- AWS SES: Requires AWS account + credentials (overkill for phase scope)
- Mailgun: Same as SendGrid (external service overhead)

**Trade-offs:**
- SMTP: No external dependency, simple, direct control. Drawback: delivery not guaranteed (SMTP success ≠ inbox delivery)
- SendGrid/Mailgun: Higher delivery reliability, bounce tracking, detailed logs. Drawback: additional service, cost, API key management

**Decision:** SMTP is appropriate for Phase 4.1. If delivery guarantees become critical later, switch to SendGrid/Mailgun.

## Email Sending (Backend)

### Async Email with BackgroundTasks

**Why BackgroundTasks (not Celery):**

| Aspect | BackgroundTasks | Celery |
|--------|---|---|
| Setup complexity | 2 lines of code | Requires Redis/RabbitMQ + worker processes |
| Latency | Sub-100ms queue time | Additional network hop |
| Failure retries | Manual; not automatic | Built-in retry logic |
| Scaling | Single process (sufficient for Phase 4.1) | Multi-process/multi-server |
| Monitoring | Basic logging | Task introspection, queue stats |

**BackgroundTasks implementation:**

```python
from fastapi import BackgroundTasks, FastAPI

app = FastAPI()

async def send_contact_email(
    to_email: str,
    subject: str,
    body: str,
    smtp_config: dict
) -> None:
    """Send email in background (fire-and-forget)."""
    try:
        send_email(to_email, subject, body, smtp_config)
        logger.info(f"Email sent to {to_email}: {subject}")
    except Exception as e:
        logger.error(f"Email send failed for {to_email}: {e}")
        # Don't raise; BackgroundTasks logs failure, doesn't bubble to user

@app.post("/contact/submit")
async def submit_contact_form(
    form_data: ContactFormRequest,

    smtp_config: dict = Depends(get_smtp_config)
) -> ContactFormResponse:
    """Accept contact form and queue email."""
    # Validate form

        to_email=HARDCODED_RECIPIENT,  # ashwin.joshi@keysight.com
```

**Failure handling:**
- Email fails silently (logged only)
- User sees "Email sent" message regardless (acceptable for Phase 4.1)
- If reliability becomes critical (Phase 5+), implement persistent queue (Redis-backed task queue)

### When to Upgrade from BackgroundTasks

**Trigger conditions for Phase 5+:**
- Need failure tracking and retry
- Need email queue persistence (survive app restart)
- Need delivery status notifications
- Need to scale beyond single server

**Upgrade path:**
1. Add Redis-backed queue (RQ or Huey, lighter than Celery)
2. Persist form submissions to DB for audit trail
3. Implement retry logic with exponential backoff
4. Add delivery status callbacks (webhooks from email provider)

### Security Constraints

**✓ DO:**
1. Load from environment variables (pydantic-settings)
2. Use application-specific SMTP account (not personal email)
3. Use TLS/SSL for SMTP connection (ssl.create_default_context())
4. Rotate password quarterly; log rotation dates
5. Log successful sends; log failures WITHOUT credentials
6. Keep .env in .gitignore

**✗ DON'T:**
1. Hardcode credentials in source files
2. Log credentials in error messages or debug output
3. Commit .env to version control
4. Use personal email account (john@keysight.com) with personal password
5. Use Basic Auth over unencrypted connections
6. Store credentials in database

### Credential Rotation Strategy

**For Phase 4.1:**
- Create application-specific SMTP account with minimal permissions (send-only)
- Store credentials in Keysight's secret manager (if available) or .env with access control
- Document password rotation schedule (quarterly recommended)

**Pre-deployment checklist:**
- [ ] SMTP credentials loaded from environment, not source code
- [ ] .env added to .gitignore (verify git status)
- [ ] Pre-commit hooks verify no credentials in logs
- [ ] SMTP connection uses TLS (port 587) or SSL (port 465)
- [ ] Error messages never include credentials

## Common Pitfalls

### 1. SMTP Connection Timeouts

**Problem:** Email send hangs for 30+ seconds, blocking request.

**Causes:**
- SMTP server unreachable (DNS failure, firewall, wrong IP)
- Network latency to mail server
- SMTP server overloaded or down

**Prevention:**
- Use timeout on SMTP connection: `smtplib.SMTP(timeout=5)`
- Test SMTP connectivity at startup (admin endpoint)
- Implement BackgroundTasks so timeout doesn't block user response

**Verification:**
```bash
# Test SMTP connectivity from deployment environment
python -c "
import smtplib
s = smtplib.SMTP('mail.keysight.com', 587, timeout=5)
s.starttls()
s.login('user', 'pass')
s.quit()
print('✓ SMTP OK')
"
```

### 2. Authentication Failures

**Problem:** SMTP login rejected (credentials invalid or expired).

**Causes:**
- Password rotated but app not updated
- Wrong username/password in .env
- Account locked (too many failed attempts)
- OAuth 2.0 required (Gmail post-2025, Outlook post-2026)

**Prevention:**
- Use application-specific passwords (not personal account passwords)
- Test credentials at startup (similar to Cyperf validation in config.py)
- Document password rotation and update procedure
- For Gmail/Outlook: switch to OAuth 2.0 before deadline

**Verification:**
```python
# In config.py __init__:
def __init__(self, **data):
    super().__init__(**data)
    # ... other validations ...
    try:
        context = ssl.create_default_context()
        with smtplib.SMTP(self.smtp_server, self.smtp_port, timeout=5) as server:
            server.starttls(context=context)
            server.login(self.smtp_username, self.smtp_password)
        logger.info("✓ SMTP credentials validated at startup")
    except Exception as e:
        logger.error(f"SMTP validation failed: {e}. App will run but email sends will fail.")
```

### 3. TLS/SSL Certificate Validation Failures

**Problem:** "certificate verify failed" error.

**Cause:** Not using `ssl.create_default_context()` (disables certificate validation).

**Prevention:**
```python
# ✓ CORRECT: validates certificates
context = ssl.create_default_context()

# ✗ WRONG: disables validation (security risk)
context = ssl.create_default_context()
context.check_hostname = False
context.verify_mode = ssl.CERT_NONE
```

### 4. Email Ending Up in Spam

**Problem:** Email reaches inbox but marked as spam.

**Causes:**
- Missing SPF, DKIM, DMARC records
- Plain text format (less likely but possible)
- Generic "no-reply" addresses

**Prevention:**
- Configure SPF, DKIM, DMARC for domain
- Use branded sender address (cyperf-tracker@keysight.com)
- Test email deliverability with MxToolbox or similar

### 5. Form Validation Bypass

**Problem:** User submits invalid email address; email fails silently.

**Prevention:**
- **Client-side:** Zod email validation (prevents invalid submission)
- **Server-side:** Pydantic EmailStr validation (catches client-side bypass)
- Never rely on client-side validation alone

### 6. Race Conditions on Form Resubmit

**Problem:** User clicks submit twice; two emails sent.

**Prevention:**
```typescript
// Frontend: disable button during submit
<button disabled={isSubmitting}>
  {isSubmitting ? "Sending..." : "Send"}
</button>

// Backend: accept duplicates gracefully (no database dedup needed for Phase 4.1)
```

### 7. Hardcoded Email Recipient Gets Out of Sync

**Problem:** `ashwin.joshi@keysight.com` becomes invalid; emails fail silently.

**Prevention:**
- Store recipient email in config/environment (not hardcoded in code)
- Log all sent emails to verify recipient
- Phase 5: Add admin panel to change recipient

### 8. Email Preview Shows HTML Escaping Issues

**Problem:** Preview displays `&lt;` instead of `<`.

**Prevention:**
- Use plain text emails (no HTML)
- If HTML needed, use proper templating (Jinja2) not f-strings

### Backend: Email Service Module

**File: `backend/services/email_service.py`**

```python
"""Email sending service for contact form submissions."""

import logging
import smtplib
import ssl
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart

logger = logging.getLogger(__name__)


class SMTPConfig:
    """SMTP configuration container."""

    def __init__(
        self,
        server: str,
        port: int,
        username: str,
        password: str,
        from_email: str,
        recipient_email: str,
    ):
        self.server = server
        self.port = port
        self.username = username
        self.password = password
        self.from_email = from_email
        self.recipient_email = recipient_email


def send_contact_email(
    to_email: str,
    subject: str,
    body: str,
    smtp_config: SMTPConfig,
    timeout: int = 10,
) -> None:
    """Send plain-text email via SMTP.

    Args:
        to_email: Recipient email address
        subject: Email subject line
        body: Plain text email body
        smtp_config: SMTP configuration
        timeout: Connection timeout in seconds

    Raises:
        SMTPException: If email send fails (should be caught by caller)
    """
    context = ssl.create_default_context()  # Validates TLS certificates

    try:
        with smtplib.SMTP(
            smtp_config.server,
            smtp_config.port,
            timeout=timeout
        ) as server:
            server.starttls(context=context)
            server.login(smtp_config.username, smtp_config.password)

            msg = MIMEText(body, "plain")
            msg["Subject"] = subject
            msg["From"] = smtp_config.from_email
            msg["To"] = to_email

            server.sendmail(
                smtp_config.from_email,
                to_email,
                msg.as_string(),
            )

        logger.info(f"Email sent to {to_email} (subject: {subject})")

    except smtplib.SMTPAuthenticationError as e:
        logger.error(
            f"SMTP authentication failed for {smtp_config.username}. "
            f"Check credentials and password rotation status."
        )
        raise
    except smtplib.SMTPException as e:
        logger.error(f"SMTP error sending to {to_email}: {e}")
        raise
    except Exception as e:
        logger.error(f"Unexpected error sending email to {to_email}: {e}")
        raise


def render_contact_email_body(
    customer_name: str,
    company: str,
    cve_id: str,
    testable: bool,
    context: str,
    cvss_score: float | None = None,
) -> str:
    """Render plain-text email body for contact submission.

    Args:
        customer_name: Full name of customer
        company: Company name
        cve_id: CVE identifier (e.g., CVE-2024-1234)
        testable: Whether CVE is testable by Cyperf
        context: "Let's Discuss" or "Request Feature"
        cvss_score: Optional CVSS v3.1 score

    Returns:
        Plain text email body
    """
    body = f"""Customer Contact: {context}

Customer Information:
  Name: {customer_name}
  Company: {company}

CVE Details:
  CVE ID: {cve_id}
  Testable by Cyperf: {"Yes" if testable else "No"}
  {f"CVSS v3.1: {cvss_score}" if cvss_score else ""}

Context: {context}

---
This contact was submitted from the Cyperf CVE Tracker.
Please follow up with the customer to discuss their needs.
"""
    return body.strip()


def render_contact_email_subject(context: str, cve_id: str) -> str:
    """Render email subject line.

    Args:
        context: "Let's Discuss" or "Request Feature"
        cve_id: CVE identifier

    Returns:
        Email subject line
    """
    if context == "discuss":
        return f"Customer Interest: {cve_id} Discussion"
    else:
        return f"Feature Request: {cve_id}"
```

### Backend: API Endpoint

**File: `backend/routes/contact.py`**

```python
"""Contact form submission endpoints."""

import logging
from typing import Annotated

from fastapi import APIRouter, BackgroundTasks, Depends, HTTPException
from pydantic import BaseModel, EmailStr, Field

from config import get_settings, Settings
from services.email_service import (
    SMTPConfig,
    render_contact_email_body,
    render_contact_email_subject,
    send_contact_email,
)

logger = logging.getLogger(__name__)
router = APIRouter(prefix="/contact", tags=["contact"])


class ContactFormRequest(BaseModel):
    """Contact form submission request."""

    first_name: str = Field(..., min_length=1, max_length=100)
    last_name: str = Field(..., min_length=1, max_length=100)
    company: str = Field(..., min_length=1, max_length=200)
    email: EmailStr
    cve_id: str = Field(..., pattern=r"^CVE-\d{4}-\d{1,7}$")
    context: str = Field(..., pattern="^(discuss|feature_request)$")


class ContactFormResponse(BaseModel):
    """Contact form submission response."""

    success: bool
    message: str
    preview: str = Field(
        ...,
        description="Plain-text preview of email sent to Ashwin"
    )


def _get_smtp_config(settings: Annotated[Settings, Depends(get_settings)]) -> SMTPConfig:
    """Dependency: get SMTP configuration from settings."""
    return SMTPConfig(
        server=settings.smtp_server,
        port=settings.smtp_port,
        username=settings.smtp_username,
        password=settings.smtp_password,
        from_email=settings.smtp_from_email,
        recipient_email=settings.smtp_recipient_email,
    )


async def _send_email_background(
    to_email: str,
    subject: str,
    body: str,
    smtp_config: SMTPConfig,
) -> None:
    """Background task: send email (fire-and-forget)."""
    try:
        send_contact_email(to_email, subject, body, smtp_config)
    except Exception as e:
        logger.error(f"Background email send failed: {e}")
        # Don't raise; BackgroundTasks will log but not bubble to user


@router.post("/submit")
async def submit_contact_form(
    form_data: ContactFormRequest,
    background_tasks: BackgroundTasks,
    smtp_config: SMTPConfig = Depends(_get_smtp_config),
) -> ContactFormResponse:
    """Submit contact form and queue email notification.

    Accepts customer contact information for a CVE of interest.
    Email is queued asynchronously; response returns immediately.
    """
    # Render email content
    subject = render_contact_email_subject(form_data.context, form_data.cve_id)
    body = render_contact_email_body(
        customer_name=f"{form_data.first_name} {form_data.last_name}",
        company=form_data.company,
        cve_id=form_data.cve_id,
        testable=True,  # TODO: fetch actual testability from DB
        context=form_data.context,
    )

    # Queue background email (non-blocking)
    background_tasks.add_task(
        _send_email_background,
        to_email=smtp_config.recipient_email,
        subject=subject,
        body=body,
        smtp_config=smtp_config,
    )

    logger.info(
        f"Contact form submitted for {form_data.cve_id} by {form_data.email}; "
        f"email queued to {smtp_config.recipient_email}"
    )

    return ContactFormResponse(
        success=True,
        message="Thank you! Your contact information has been sent.",
        preview=body,
    )
```

```typescript
  context,
  isOpen,
  onClose,
}: ContactFormSidebarProps) {
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [submitSuccess, setSubmitSuccess] = useState(false);
  const [emailPreview, setEmailPreview] = useState('');

  const form = useForm<ContactFormData>({
    resolver: zodResolver(contactFormSchema),
    defaultValues: {
      first_name: '',
      last_name: '',
      company: '',
      email: '',
    },
  });

  const onSubmit = async (data: ContactFormData) => {
    setIsSubmitting(true);
    try {
      const response = await fetch('/contact/submit', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          ...data,
          cve_id: cveId,
          context,
        }),
      });

      if (!response.ok) throw new Error('Form submission failed');

      const result = await response.json();
      setEmailPreview(result.preview);
      setSubmitSuccess(true);

      // Auto-close after 3 seconds
      setTimeout(() => {
        onClose();
        form.reset();
        setSubmitSuccess(false);
        setEmailPreview('');
      }, 3000);
    } catch (error) {
      form.setError('root', { message: 'Failed to submit. Please try again.' });
    } finally {
      setIsSubmitting(false);
    }
  };

  const title =
    context === 'discuss'
      ? `Let's Discuss ${cveId}`
      : `Request Feature: ${cveId}`;

  return (
    <Sheet open={isOpen} onOpenChange={onClose}>
      <SheetContent side="right" className="w-96">
        <SheetHeader>
          <SheetTitle>{title}</SheetTitle>
        </SheetHeader>

        <div className="mt-6 space-y-4">
          {!submitSuccess ? (
            <Form {...form}>
              <form onSubmit={form.handleSubmit(onSubmit)} className="space-y-4">
                <FormField
                  control={form.control}
                  name="first_name"
                  render={({ field }) => (
                    <FormItem>
                      <FormLabel>First Name</FormLabel>
                      <FormControl>
                        <Input placeholder="John" {...field} />
                      </FormControl>
                      <FormMessage />
                    </FormItem>
                  )}
                />

                <FormField
                  control={form.control}
                  name="last_name"
                  render={({ field }) => (
                    <FormItem>
                      <FormLabel>Last Name</FormLabel>
                      <FormControl>
                        <Input placeholder="Doe" {...field} />
                      </FormControl>
                      <FormMessage />
                    </FormItem>
                  )}
                />

                <FormField
                  control={form.control}
                  name="company"
                  render={({ field }) => (
                    <FormItem>
                      <FormLabel>Company</FormLabel>
                      <FormControl>
                        <Input placeholder="Acme Corp" {...field} />
                      </FormControl>
                      <FormMessage />
                    </FormItem>
                  )}
                />

                <FormField
                  control={form.control}
                  name="email"
                  render={({ field }) => (
                    <FormItem>
                      <FormLabel>Email</FormLabel>
                      <FormControl>
                        <Input placeholder="john@acme.com" type="email" {...field} />
                      </FormControl>
                      <FormMessage />
                    </FormItem>
                  )}
                />

                <Button
                  type="submit"
                  disabled={isSubmitting}
                  className="w-full"
                >
                  {isSubmitting ? 'Sending...' : 'Send'}
                </Button>

                {form.formState.errors.root && (
                  <p className="text-sm text-red-500">
                    {form.formState.errors.root.message}
                  </p>
                )}
              </form>
            </Form>
          ) : (
            <div className="space-y-4">
              <p className="text-sm font-medium text-green-600">
                ✓ Email sent successfully
              </p>
              <div className="bg-gray-900 p-4 rounded-lg text-xs whitespace-pre-wrap font-mono text-gray-300">
                {emailPreview}
              </div>
              <p className="text-xs text-gray-400">
                Closing in 3 seconds...
              </p>
            </div>
          )}
        </div>
      </SheetContent>
    </Sheet>
  );
}
```

## Key Decisions for Phase 4.1

| Decision | Rationale |
|----------|-----------|
| **Email service:** Python smtplib + FastAPI BackgroundTasks | Simple, no external deps; fire-and-forget acceptable |
| **Credentials:** Environment variables via pydantic-settings | Matches Cyperf pattern; secure by default |
| **Form pattern:** React Hook Form + Zod + shadcn/ui Sheet | Type-safe; minimal re-renders; matches stack |
| **Email format:** Plain text (no HTML) | Safer; sufficient for MVP |
| **Data persistence:** Stateless (no database) | Simplifies Phase 4.1; add in Phase 5 if needed |
| **Failure handling:** Log only (fire-and-forget) | Acceptable for Phase 4.1; upgrade in Phase 5 |
| **SMTP timeout:** 10 seconds | Balances responsiveness with reliability |
| **Background job:** BackgroundTasks (NOT Celery) | Scales to thousands daily; avoids Redis/RabbitMQ setup |
