## Overview

Implement the server-side email pipeline: SMTP configuration via pydantic-settings, a stateless `email_service.py` module for email composition and sending, and a `POST /contact/submit` FastAPI endpoint that validates the form payload, renders the email body, queues the send via `BackgroundTasks`, and returns the email preview to the caller immediately.

### Task 2: Create `backend/services/email_service.py`

New file. Contains three pure functions with no FastAPI dependencies — testable in isolation.

**`SMTPConfig` dataclass** — typed container for SMTP connection parameters. Fields: `server`, `port`, `username`, `password`, `from_email`, `recipient_email`.

**`render_email_subject(context: str, cve_id: str) -> str`** — generates subject line:
- `context == "discuss"` → `"Customer Interest: {cve_id} Discussion"`
- `context == "feature_request"` → `"Feature Request: {cve_id}"`
- Any other value → `"CVE Inquiry: {cve_id}"` (defensive fallback, log warning)

**`render_email_body(first_name, last_name, company, customer_email, cve_id, testable, context, cvss_score=None, attack_profiles=None) -> str`** — returns a clean plain-text email body. Format:

```
Customer Contact: {context_label}

Customer Information:
  Name: {first_name} {last_name}
  Company: {company}
  Email: {customer_email}

CVE Details:
  CVE ID: {cve_id}
  Testable by Cyperf: {Yes/No}
  CVSS v3.1: {cvss_score or "N/A"}
  Attack Profiles: {comma-joined list or "None"}

Context: {context_label}

---
This contact was submitted via the Cyperf CVE Tracker.
Please follow up with the customer to discuss their needs.
```

`context_label` mapping: `"discuss"` → `"Let's Discuss"`, `"feature_request"` → `"Request Feature"`.

**`send_contact_email(to_email, subject, body, smtp_config, timeout=10) -> None`** — sends via `smtplib.SMTP` with STARTTLS. Uses `ssl.create_default_context()` (certificate validation enabled — never disable). Raises on all exceptions so the caller (background task wrapper) can catch and log.

Implementation constraints:
- `timeout=10` on `smtplib.SMTP(...)` call to prevent indefinite blocking.
- Log successful send at INFO level: `f"Email sent to {to_email} subject='{subject}'"`.
- On `SMTPAuthenticationError`: log error message that includes `smtp_config.username` (redact password) and re-raise.
- On `SMTPException` or any other exception: log `f"Email send failed to {to_email}: {type(e).__name__}: {e}"` and re-raise.
- Never log `smtp_config.password` in any code path.

**Success criteria:**
- `render_email_subject("discuss", "CVE-2024-1234")` returns `"Customer Interest: CVE-2024-1234 Discussion"`.
- `render_email_subject("feature_request", "CVE-2024-5678")` returns `"Feature Request: CVE-2024-5678"`.
- `render_email_body(...)` output contains customer name, company, CVE ID, testability status.
- Module imports cleanly with no external dependencies beyond stdlib.

### Task 3: Create `backend/routes/contact.py`

New file. Implements `POST /contact/submit`.

**Pydantic models:**

```python
class ContactFormRequest(BaseModel):
    first_name: str = Field(..., min_length=1, max_length=100, strip_whitespace=True)
    last_name: str = Field(..., min_length=1, max_length=100, strip_whitespace=True)
    company: str = Field(..., min_length=1, max_length=200, strip_whitespace=True)
    email: EmailStr
    cve_id: str = Field(..., pattern=r"^CVE-\d{4}-\d{1,7}$")
    context: Literal["discuss", "feature_request"]
    testable: bool = False
    cvss_score: float | None = None
    attack_profiles: list[str] = Field(default_factory=list)

class ContactFormResponse(BaseModel):
    success: bool
    message: str
    preview: str   # Plain-text copy of email body shown to user
```

**Dependency `_get_smtp_config(settings: Settings) -> SMTPConfig`** — builds `SMTPConfig` from settings. Injected via `Depends`.

**Background wrapper `_send_email_background(to_email, subject, body, smtp_config) -> None`** — calls `send_contact_email`, catches all exceptions, logs failure without re-raising (fire-and-forget contract).

**Endpoint `POST /contact/submit`:**
1. Validate request via Pydantic (automatic — 422 on failure).
2. Call `render_email_subject(form_data.context, form_data.cve_id)`.
3. Call `render_email_body(...)` passing all form fields plus testable/cvss/attack_profiles from payload.
4. Call `background_tasks.add_task(_send_email_background, ...)`.
5. Log: `f"Contact form submitted cve={form_data.cve_id} context={form_data.context} from={form_data.email}"` — never log name/company (PII minimization).
6. Return `ContactFormResponse(success=True, message="Thank you. Your information has been sent.", preview=body)`.

Router: `APIRouter(prefix="/contact", tags=["contact"])`.

**Success criteria:**
- `POST /contact/submit` with valid payload returns HTTP 200 with `success=true` and non-empty `preview`.
- `POST /contact/submit` with missing field returns HTTP 422.
- `POST /contact/submit` with invalid CVE ID format (e.g. `"not-a-cve"`) returns HTTP 422.
- `POST /contact/submit` with invalid email returns HTTP 422.
- Endpoint returns immediately (does not block on email send).
