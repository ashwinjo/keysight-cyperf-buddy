## Overview

Wire the `ContactFormSidebar` into the two existing page components where the sales funnel is triggered. The Search page CVE detail view gets both buttons ("Let's Discuss" when testable, "Request Feature" when not testable). The Browse page gets a "Request Feature" action on rows (all browse rows are testable=true by current filter, so only the Search page has the "Request Feature" path for testable=false CVEs — see specifics).

### Task 1: Audit button placement rules against current page structure

Before writing any code, confirm the exact placement rules from CONTEXT.md:

- **"Let's Discuss"** — CVE detail view only (the expanded card in `SearchPage.tsx` that appears after a search result loads). Visible when `cveResult.testable === true`.
- **"Request Feature"** — CVE detail view in `SearchPage.tsx` when `cveResult.testable === false`. Also available on Browse page rows (though Browse currently filters to testable-only, a "Let's Discuss" action per row is still appropriate there).

Confirmed page locations:
1. `SearchPage.tsx` — CVE detail card (`{cveResult && ...}` block, lines ~60+). Add action buttons at the bottom of the card.
2. `BrowsePage.tsx` — Per-row action column in the data table. Browse shows only testable=true CVEs, so the button label should be "Let's Discuss" for browse rows.

Rationale for Browse rows: The Browse page shows Cyperf-testable CVEs. A "Let's Discuss" button on each row gives users a fast path to engage for CVEs they see while browsing — this is the high-intent surface.

### Task 2: Add action buttons to `SearchPage.tsx` CVE detail view

In the existing `{cveResult && (...)}` detail card block in `SearchPage.tsx`:

1. Add state at the top of the component:
   ```typescript
   const [contactSidebarOpen, setContactSidebarOpen] = useState(false);
   const [contactContext, setContactContext] = useState<ContactContext>('discuss');
   ```

2. Add a helper:
   ```typescript
   const openSidebar = (ctx: ContactContext) => {
     setContactContext(ctx);
     setContactSidebarOpen(true);
   };
   ```

3. At the **bottom of the CVE detail card** (after the attack profiles section, before the closing `</div>`), insert an action row:

   ```tsx
   <div className="pt-4 border-t border-luxury-border flex gap-3">
     {cveResult.testable ? (
       <button
         onClick={() => openSidebar('discuss')}
         className="px-4 py-2 bg-emerald-700 hover:bg-emerald-600 text-white text-sm font-semibold rounded transition-colors"
       >
         Let's Discuss
       </button>
     ) : (
       <button
         onClick={() => openSidebar('feature_request')}
         className="px-4 py-2 bg-luxury-bg-subtle hover:bg-luxury-accent/10 border border-luxury-accent/40 text-luxury-accent text-sm font-semibold rounded transition-colors"
       >
         Request Feature
       </button>
     )}
   </div>
   ```

   Button styling rationale:
   - "Let's Discuss" (testable): solid emerald — action is high-value, warm call to action.
   - "Request Feature" (not testable): subtle outlined — softer signal, lower intent path.

4. At the bottom of `SearchPage`'s JSX return (sibling to the main content `div`), render the sidebar:

   ```tsx
   {cveResult && (
     <ContactFormSidebar
       isOpen={contactSidebarOpen}
       onClose={() => setContactSidebarOpen(false)}
       cveId={cveResult.id}
       testable={cveResult.testable}
       context={contactContext}
       cvssScore={cveResult.cvss_v3_1_score ?? null}
       attackProfiles={cveResult.attack_profiles}
     />
   )}
   ```

5. Import `ContactFormSidebar` and `ContactContext` at the top of the file.

**Success criteria:**
- When searching for a testable CVE: green "Let's Discuss" button appears in detail card.
- When searching for a non-testable CVE: outlined "Request Feature" button appears in detail card.
- Neither button appears before a search is performed.
- Clicking either button opens the sidebar in the correct context.
- Sidebar closes correctly when user clicks close or submits.

### Task 3: Add `onRowAction` callback to `DataTable.tsx` and wire Browse rows

The DataTable is shared and should support optional row actions without breaking existing callers.

**Step 3a — Extend DataTable props:**

```typescript
interface DataTableProps {
  data: CVEResponse[];
  isLoading: boolean;
  onSort: (column: SortState['column']) => void;
  sortState: SortState;
  // New optional prop — if provided, renders an action column
  onRowAction?: (cve: CVEResponse) => void;
  rowActionLabel?: string;
}
```

**Step 3b — Conditional action column in DataTable:**

If `onRowAction` is provided, render an extra column in the `<thead>` and a button cell in each `<tbody>` row:

```tsx
// In thead:
{onRowAction && (
  <th className="px-6 py-4 text-left font-semibold text-luxury-accent text-xs tracking-luxury uppercase">
    Action
  </th>
)}

// In each tbody row:
{onRowAction && (
  <td className="px-6 py-4">
    <button
      onClick={() => onRowAction(cve)}
      className="px-3 py-1.5 text-xs font-semibold bg-emerald-700 hover:bg-emerald-600 text-white rounded transition-colors whitespace-nowrap"
    >
      {rowActionLabel ?? "Let's Discuss"}
    </button>
  </td>
)}
```

Existing DataTable callers (`SearchPage`, `BrowsePage`) that do not pass `onRowAction` are unaffected — the column does not render.

**Step 3c — Wire Browse page:**

In `BrowsePage.tsx`:

1. Add state:
   ```typescript
   const [contactSidebarOpen, setContactSidebarOpen] = useState(false);
   const [selectedCVE, setSelectedCVE] = useState<CVEResponse | null>(null);
   ```

2. Handler:
   ```typescript
   const handleRowAction = (cve: CVEResponse) => {
     setSelectedCVE(cve);
     setContactSidebarOpen(true);
   };
   ```

3. Pass to `DataTable`:
   ```tsx
   <DataTable
     data={filteredData}
     isLoading={isLoading}
     sortState={sortState}
     onSort={handleSort}
     onRowAction={handleRowAction}
     rowActionLabel="Let's Discuss"
   />
   ```

4. Render sidebar at bottom of page (conditionally on `selectedCVE`):
   ```tsx
   {selectedCVE && (
     <ContactFormSidebar
       isOpen={contactSidebarOpen}
       onClose={() => {
         setContactSidebarOpen(false);
         setSelectedCVE(null);
       }}
       cveId={selectedCVE.id}
       testable={selectedCVE.testable}
       context="discuss"
       cvssScore={selectedCVE.cvss_v3_1_score ?? null}
       attackProfiles={selectedCVE.attack_profiles}
     />
   )}
   ```

5. Import `ContactFormSidebar`, `ContactContext`, `CVEResponse` at the top of `BrowsePage.tsx`.

**Success criteria:**
- Browse page table renders a new "Action" column with "Let's Discuss" per row.
- Clicking any row's button opens the sidebar with that CVE's data pre-loaded.
- The sidebar close handler resets `selectedCVE` to null (prevents stale data on second open).
- Existing DataTable callers with no `onRowAction` prop render identically to before.
- TypeScript compiles cleanly.
