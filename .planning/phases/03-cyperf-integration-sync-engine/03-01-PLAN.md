<task type="auto">
  <name>Task 2: Implement CyperfService for API client + profile/CVE extraction</name>
  <files>backend/services/cyperf_service.py</files>
  <action>
Create backend/services/cyperf_service.py with the following:

**Class CyperfService:**
- __init__(controller_ip: str, username: str, password: str) — Initialize cyperf-api-wrapper client with credentials
- async fetch_attack_profiles() -> List[AttackProfile] — Query all attack profiles from Cyperf Controller; return raw profile objects
- extract_cves_from_profiles(profiles: List[AttackProfile]) -> Dict[str, str] — Parse profile metadata; extract CVE IDs and map to profile names; return {cve_id: profile_name}
- async sync_cyperf_cves() -> SyncResult — Orchestrator: fetch profiles → extract CVEs → prepare for database upsert; return SyncResult(profiles_fetched, cves_extracted, error)

**SyncResult dataclass:**
- profiles_fetched: int
- cves_extracted: int
- error: Optional[str] = None

**Error Handling:**
- Network/connection errors → log at ERROR level, include retry_count context, raise CyperfConnectionError
- Cyperf API errors (e.g., 401 invalid credentials) → log at ERROR level with error code, raise CyperfAPIError
- Profile parsing errors → log at WARN level (don't fail entire sync), skip malformed profile, continue processing
- Do NOT log full API responses; only summary (e.g., "Fetched 1247 profiles")
- Do NOT log credentials; only log "Cyperf Controller {ip}" and job metadata

**Logging (use Python logging):**
- INFO: "Starting Cyperf sync...", "Fetched {N} profiles", "Extracted {M} CVEs from profiles"
- ERROR: Connection failures, API errors (code + message only, no credentials)
- Include context: start_time, duration (computed after fetch completes)

**Pagination handling (if cyperf-api-wrapper supports limit/offset):**
- Fetch with pagination if available; otherwise fetch all in one call
- Accumulate results across pages
- Include page_count and total_count in logging

**Return structure:** SyncResult should be used by scheduler job (Task 3) to record in sync_metadata table.
